# VibeSort — Telegram-бот для любимых треков

Тестовая версия: Spotify → любимые треки → теги Last.fm → просмотр подборок → создание приватных плейлистов по кнопке. Также можно отправить CSV-файл с треками без Spotify и скачать подборки отдельными CSV-файлами. Интерфейс находится в Telegram; веб-сервер нужен только для возвращения со страницы входа Spotify и проверки работоспособности хостингом.

## Что работает

- Синий Telegram Mini App: кнопка в меню бота и в `/start`, загрузка скриншота, редактирование распознанного списка, фоновой разбор, карточки по жанрам и настроению, копирование и скачивание TXT. `/app` также показывает интерфейс в браузере, но операции требуют подписи Telegram.
- Фото можно отправить прямо в чат. Бот сначала показывает распознанные строки и просит подтвердить разбор. Фото передаётся Provod AI, поэтому используется баланс провайдера. Сам файл приложение на диск не сохраняет; правила хранения у провайдера действуют отдельно.
- В Bothost добавь `PROVOD_API_KEY` из своего кабинета, `AI_BASE_URL=https://api.provod.ai/v1`, `AI_VISION_MODEL=gpt-4o-mini` (или доступную у тебя модель с поддержкой изображений). Настоящий вызов Provod нужно проверить на скриншоте после добавления ключа: модель в конкретном аккаунте может быть недоступна. Ни ключи, ни баланс нельзя получить из другого бота автоматически.
- `SPOTIFY_CLIENT_ID` и `SPOTIFY_CLIENT_SECRET` больше не обязательны для запуска. Без API Spotify создаются списки, а ссылки открывают поиск песен; автоматическое создание плейлистов из скриншотов не реализовано.
- После обновления из Git меню Mini App настраивается автоматически при старте. Веб-порт должен совпадать с системным `PORT` Bothost (у текущего развёртывания 8000).
- Фоновые задания Mini App доступны до 24 часов в памяти процесса: при перезапуске незавершённый разбор нужно повторить. После `/disconnect` результаты веб-заданий пользователя удаляются. Массовую производственную нагрузку ещё не проверяли; одновременно принимаются до 8 разборов Mini App.
- Обычное сообщение: `Исполнитель — Название`, каждый трек с новой строки (также поддерживаются ` - ` и ` – `). Подключение Spotify не нужно; нужен Last.fm API key. Можно посмотреть подборки и скачать TXT или CSV.
- `/connect`: Spotify OAuth Authorization Code + PKCE, обновление токенов.
- `/scan`: последние 300 лайков по умолчанию; пагинация, пропуск недоступных треков, удаление дублей.
- Жанры и приблизительные настроения по явным тегам Last.fm. Нет подходящих тегов — «Без категории». Жанр не считается признаком настроения. Один трек может попасть в несколько групп.
- Просмотр примеров, затем отдельная кнопка создания приватного плейлиста в Spotify.
- `/demo`: вымышленные треки, без запросов к Spotify и без возможности экспорта.
- `/import`: отправка UTF-8 CSV до 1 МБ, до 300 уникальных треков. Столбцы `artist,title` или `Artist Name(s),Track Name`. Подборки скачиваются CSV-файлами и не создаются в музыкальном сервисе автоматически. Для импорта также нужен `LASTFM_API_KEY`.
- `/privacy`, `/disconnect`, `/id`; бот работает в личном чате. При необходимости можно ограничить доступ через `ALLOWED_TELEGRAM_IDS`.
- Токены и черновики зашифрованы в SQLite. Одноразовые OAuth-ссылки на 10 минут; черновики доступны 24 часа. Приложение не пишет OAuth-запросы в access log.
- Повторная кнопка одного черновика возвращает готовый плейлист. После неоднозначной ошибки записи бот требует проверить Spotify вручную, чтобы не создавать дубли. Новый разбор создаёт новый черновик и может создать новый плейлист с тем же названием.

**Пока нет:** прямого подключения Яндекс Музыки и других платформ, рекламы, донатов, подписок, автосинхронизации, полноценного анализа аудио. Жанры и вайб зависят от качества пользовательских тегов Last.fm. При сбое Last.fm весь разбор прерывается, чтобы не выдавать сбой за отсутствие тегов.

## Установка на Bothost — без знания Docker

**Для текущего Mini App Spotify настраивать не нужно.** Обязательные значения: `BOT_TOKEN`, `PUBLIC_BASE_URL`, `TOKEN_ENCRYPTION_KEY`; для жанров — `LASTFM_API_KEY`; для фото — `PROVOD_API_KEY`. `DATA_DIR=/app/data`; `PORT` берётся из Bothost. Старые Spotify-ключи можно оставить, но шаги настройки Spotify ниже нужны только для тестового старого сценария.

1. Создай бота в официальном [@BotFather](https://t.me/BotFather): `/newbot`. Сохрани выданный токен. Не публикуй его и не присылай в переписку.
2. В Bothost создай Python-бота из ZIP-архива этого проекта. В корне должны лежать `main.py`, `requirements.txt`, `vibekeeper/`. Главный файл — **`main.py`**, Python **3.12**, команда запуска при необходимости — `python main.py`. Также можно использовать приватный Git-репозиторий. Зависимости перечислены в `requirements.txt`.
3. Включи домен/веб-доступ. Bothost может предоставить поддомен (доступность зависит от тарифа). Оставь порт **3000**, заданный Bothost. Код читает системную переменную `PORT` и слушает `0.0.0.0` на этом порту. Скопируй HTTPS-адрес: например, `https://my-bot.bothost.tech`. Telegram-вебхук не настраивай: бот использует polling; HTTP-сервер нужен для Spotify OAuth.
4. В [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) создай интеграцию с Web API. В Redirect URIs добавь **`https://ТВОЙ-ДОМЕН/oauth/spotify`** — именно свой адрес, с точным совпадением символов. Запиши Client ID и Client Secret. В Users Management добавь свой Spotify email в разрешённых пользователей. Владелец приложения должен иметь Spotify Premium.
5. Получи [Last.fm API key](https://www.last.fm/api/account/create). Для поиска тегов нужен только API key, не пароль и не shared secret. Бесплатный тест не означает автоматического разрешения коммерческого использования, см. ограничения ниже.
6. В разделе переменных окружения Bothost заполни:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | Токен от BotFather |
   | `SPOTIFY_CLIENT_ID` | Client ID из Spotify |
   | `SPOTIFY_CLIENT_SECRET` | Client Secret из Spotify |
   | `PUBLIC_BASE_URL` | Свой HTTPS-домен, без последнего `/` и без `/oauth/spotify` |
   | `TOKEN_ENCRYPTION_KEY` | Постоянный ключ Fernet, как получить — ниже |
   | `ALLOWED_TELEGRAM_IDS` | Необязательно. Пустое значение — доступ всем; несколько ID — через запятую |
   | `LASTFM_API_KEY` | API key от Last.fm |
   | `DATA_DIR` | `/app/data` |
   | `PORT` | Системная переменная Bothost. Вручную добавлять или менять не нужно |
   | `SCAN_LIMIT` | `300`, для первого теста можно `30` |

   `ALLOWED_TELEGRAM_IDS` можно не создавать. Если ранее там стояло `1`, удали переменную или очисти значение. Telegram ID для ограничения доступа можно узнать через `/id`.

   В терминале Bothost после установки зависимостей сгенерируй ключ:

   ```bash
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```

   Скопируй его в `TOKEN_ENCRYPTION_KEY`. Не меняй ключ при обновлении: старые токены станут нечитаемыми. Не добавляй значения переменных в исходники/ZIP. Если терминал недоступен до первой установки, сначала выполни сборку, затем открой терминал, добавь ключ и перезапусти.

7. Запусти **один экземпляр** бота. Открой `https://ТВОЙ-ДОМЕН/health`: должен быть ответ `{"status": "ok"}`. При 502 проверь домен и совпадение порта в панели и `PORT`.
8. В Telegram: `/start` → `/demo` → `/privacy` → `/connect` → вход в Spotify → `/scan` → подборка → «Создать в Spotify». Для загрузки списка без Spotify: `/import` → отправить CSV-файл → подборка → «Скачать CSV». Первые разборы лучше делать с `SCAN_LIMIT=30`: на 300 треков поиск тегов может занять несколько минут. Полный список будет записан в плейлист; предпросмотр показывает только пять примеров.

Здесь не требуется устанавливать Docker вручную. Bothost самостоятельно собирает окружение. Если тариф не даёт HTTPS-домен, сначала потребуется включить такую возможность: без обратного адреса Spotify подключение не завершится.

Официальные инструкции Bothost: [каталог документации](https://bothost.ru/docs/), [домены и порты](https://bothost.ru/docs/domains-and-ports), [переменные окружения](https://bothost.ru/docs/environment-variables). Храни базу в `/app/data`, чтобы обновление исходников её не удалило. Уточни сохранность этой папки на своём тарифе.

## Локальный запуск и проверка

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
# Заполнить .env; для OAuth нужен настроенный HTTPS-адрес.
.venv/bin/python main.py
```

Тесты без реальных аккаунтов:

```bash
.venv/bin/python -m pytest -q
```

`requirements.lock.txt` фиксирует версии runtime-зависимостей, на которых проверена эта сборка. Для воспроизводимой установки можно устанавливать его вместо `requirements.txt`.

## Ограничения перед публичным запуском

- [Spotify quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes): в development mode до 5 разрешённых пользователей; Premium владельца не снимает ограничений. Массовый запуск требует отдельного доступа.
- [Spotify Developer Policy](https://developer.spotify.com/policy): запрещено передавать Spotify Content в AI/ML-модели. Здесь нет AI и скачивания/воспроизведения аудио. Само отсутствие AI не гарантирует одобрения: сценарий сортировки, использование метаданных, передача названий в Last.fm и коммерческая модель требуют отдельной проверки по правилам Spotify перед публикацией.
- [Last.fm API terms](https://www.last.fm/api/tos): до рекламы, донатов в коммерческом продукте или подписок нужно согласовать предполагаемое использование с Last.fm. Текущий адаптер выбран для закрытого эксперимента, а не как обещание бесплатной коммерческой инфраструктуры.
- [Telegram Stars](https://core.telegram.org/bots/payments-stars): цифровые платные функции внутри Telegram продаются через Stars. Платежей в этой сборке нет.
- `/disconnect` удаляет данные из рабочей базы, не из сообщений Telegram, плейлистов Spotify и резервных копий хостинга. Для публичного сервиса нужна собственная политика резервного копирования и удаления. Шифрование не заменяет контроль доступа к серверу и ключу.
- Черновики недоступны после 24 часов; просроченные записи удаляются при старте и затем каждый час. Прерванный перезапуском разбор запускается заново. Фоновой очереди и автоматического возобновления нет.
- За reverse proxy нужно отключить запись query string для `/oauth/spotify`: приложение уже отключает access log, но не управляет логами Bothost.

## Как расширять

`models.MusicProvider` задаёт интерфейс чтения библиотеки и записи плейлистов. `providers.Spotify` — первый адаптер. `classifier.py` содержит редактируемые правила; `service.py` управляет разбором и экспортом независимо от Telegram. Для Яндекса нужны свой адаптер и безопасное подключение аккаунта. Официальный массовый доступ каждой платформы проверяется отдельно.
