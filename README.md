# VibeSort

Telegram-бот и синий Mini App для сортировки музыкальных списков. Фото, текст и публичная Spotify-ссылка → проверка списка → подборки → постоянная библиотека.

## Изменения v3

- Центрированная навигация **Добавить / Библиотека / Настройки**. Верхняя кнопка сброса удалена. Способы ввода разнесены по вкладкам Фото / Ссылка / Текст, пояснения сокращены.
- Фото уменьшается в браузере до JPEG с длинной стороной 2000 px. Распознавание работает фоновым заданием: запрос на загрузку не ждёт до 90 секунд ответа AI. Статус опрашивается отдельно, временные сетевые сбои повторяются, есть кнопка возобновления проверки. При повторном открытии можно восстановить известное клиенту задание. Перезапуск самого сервера прерывает активные задания.
- После нового скриншота сбрасывается привязка к предыдущему Spotify-импорту. Раньше смешение источников могло ошибочно отключать AI-резерв и оставлять все треки без категории.
- Фонк (`phonk`) и фанк (`funk`, включая baile funk) — отдельные категории. Slowed/reverb не считаются самостоятельным жанром. Если нет тегов конкретной песни, ищем жанровые теги исполнителя; настроения исполнителя не переносятся на все песни.
- Для введённых списков и фото недостающие теги может оценить Provod AI. В настройках это можно выключить. Оценки подписаны; аудио не анализируется, точность не гарантируется.
- Для публичного Spotify-списка AI не используется. Если Last.fm не даёт теги, список сохраняется без выдуманных категорий. Пользователь может самостоятельно указать жанр для списка перед разбором либо для неопределённых песен прямо в сохранённой подборке.
- Готовые подборки автоматически сохраняются в зашифрованной SQLite-библиотеке. Они переживают перезапуск и не удаляются вместе с суточными черновиками. Доступны просмотр всех треков, переименование, удаление, копирование и TXT. В списке библиотеки показываются последние 50 загрузок.
- Для треков с точной Spotify-ссылкой можно открыть официальный встроенный плеер. Это **не создание нового Spotify-плейлиста** и не обещание полного воспроизведения: условия Spotify и возможности аккаунта сохраняются. Для названий без идентификатора доступна ссылка на поиск. Новые списки в Spotify требуют рабочего OAuth/API-доступа; текущий отказ 403 этим обновлением не устраняется.
- Публичные ссылки Spotify пробуются повторно через два обычных варианта адреса виджета. Успешный ответ кэшируется на сутки и может использоваться при временном отказе; использование копии отмечается. Отказ страницы с сервера больше не объявляется доказательством приватности плейлиста. Разные IP/регионы могут получать разные ответы; гарантировать импорт любой ссылки без API невозможно.

## Bothost

Обновить код из Git, один процесс, главный файл `main.py`. Python 3.11 или 3.12. Собственный Dockerfile не требуется. Домен должен быть включён. Значение порта в панели должно совпадать с системным `PORT`; у текущего развёртывания используется **8000**, менять его не нужно.

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен Telegram из BotFather |
| `PUBLIC_BASE_URL` | HTTPS-домен без пути, например `https://my-bot.bothost.tech` |
| `TOKEN_ENCRYPTION_KEY` | Постоянный ключ Fernet. Не менять при обновлениях |
| `DATA_DIR` | `/app/data` — постоянная папка Bothost |
| `LASTFM_API_KEY` | API key Last.fm, не shared secret |
| `PROVOD_API_KEY` | Ключ Provod AI |
| `AI_BASE_URL` | `https://api.provod.ai/v1` |
| `AI_VISION_MODEL` | Доступная vision-модель, например `gpt-4o-mini` |
| `AI_TAG_MODEL` | Необязательно: модель резервных тегов. По умолчанию модель фото |
| `ALLOWED_TELEGRAM_IDS` | Необязательно. Пусто — доступ всем |
| `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` | Необязательно, для старого OAuth-сценария `/connect` и `/scan` |

Ключи вводятся в панели Bothost, не в репозитории. После обновления перезапустить бот, закрыть Mini App полностью и открыть через `/start`. Кнопка меню Mini App настраивается ботом автоматически. `/health` возвращает `{"status":"ok"}`. Консоль не нужна для обычного обновления.

Если постоянного ключа шифрования ещё нет, его можно сгенерировать там, где установлен Python с cryptography:

```sh
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Фото и AI-классификация расходуют баланс Provod. Разбор отправляет имена исполнителей и названия в Last.fm; резерв для фото/текста — в Provod. Фото отправляется Provod для распознавания, не сохраняется приложением на диск. Перед первым разбором доступна политика `/privacy`. Готовая библиотека хранится до удаления пользователем, черновики и завершённые задания — до суток. `/disconnect` или удаление данных из настроек очищает аккаунт, библиотеку и настройки пользователя из рабочей базы. Бэкапы и сообщения Telegram регулируются отдельно.

## Возможности и ограничения

- До 300 строк за раз; один трек может попасть в несколько жанровых и атмосферных подборок.
- Сервер принимает до 8 одновременных заданий Mini App. На пользователя — одно задание. Очередь и баланс AI ограничены ресурсами хостинга; промышленная нагрузка не проверена.
- Проверяется HMAC-подпись Telegram initData и срок действия сессии. Подборки, задания и настройки привязаны к владельцу. Обновлённая библиотека зашифрована тем же Fernet-ключом, что и Spotify-токены.
- Импорт Spotify скачивает только обычную публичную страницу виджета по фиксированному домену, не следует произвольным перенаправлениям и ограничивает размер ответа. Ни извлечения приватных токенов, ни обхода авторизации, ни скачивания аудио нет.
- Для публичного коммерческого запуска нужно отдельно проверить условия Spotify и коммерческого использования Last.fm. Платежи и реклама пока не реализованы.

## Разработка

```sh
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
# Заполнить .env
.venv/bin/python main.py
.venv/bin/python -m pytest -q
```

`requirements.txt` — плоский список зависимостей для сборщика Bothost. `requirements.lock.txt` фиксирует исходные runtime-версии. Сервер: aiohttp + aiogram; клиент: HTML/CSS/JS без сборки. Проверки не вызывают реальные платные AI-запросы.
